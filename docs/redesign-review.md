# 재구성 명세 검토 기록

검토 대상은 수정 전 `redesign-plan.md`의 SHA-256 `19340a3e7995cdab89ac30e9586b24757e737abd6ab483ec0b064eddc23d5ac7`이다. 아래 줄 번호는 수정 전66줄 명세 기준이다. 원래 사용자 요구사항, 원문3·4·5절, 고정 설정·실제 계산·검증·보고 코드를 대조했다.

판정: 수정 전 문서는 실행 계약으로 쓰기에 조건이 부족했다. 아래8개 항목을 [명세 v2](redesign-plan.md)에 반영했다. 새 금융 계산이나 실험 실행은 하지 않았다.

## R1 · P1 · 비교 질문과 B 설정이 닫혀 있지 않음

- 위치: 수정 전9–13줄. A를 앞에 둔다는 설명만 있고 B의 평가창·XGB·가중치·평균·공분산·거래 조건이 구체적이지 않았다. 구현자가 A 또는 F141 설정을 임의로 골라 새 ‘주 결과’를 만들 수 있었다.
- 근거: [A/B 설정](../configs/protocol.json)과 [후속 설정](../configs/followup_protocol.json)은 같은 세 CER 대비를 사용하면서 학습 이력·모형 용량·거래 정책이 다르다.
- 반영: A51/B51/F141/D51 ID와 질문을 분리하고 기준 설정을 표로 확정했다. 기존 사전 고정 기록의 지위를 보고 순서 변경으로 소급 바꾸지 않는다.

## R2 · P1 · 원문 배분 우위를 XGBoost 효과로 읽을 위험

- 위치: 수정 전13·53–55줄. A의 비교에 포함된 배분 파라미터 변경을 분리하지 않았다.
- 근거: [원문4.3절](https://arxiv.org/html/2406.09578v2#S4.SS3)과 실제 설정은 기본 MV의 위험회피5·거래벌점0을 국면형에서10·1로 바꾼다. 현금 규칙도 예측과 결합된다.
- 반영: A는 배분 묶음 비교, ML의 추가 가치는 B 내부 비교로 한정했다. M05/M06에 동일 최적화 조건에서 예상수익 생성방식만 다른 진단을 명시했다. 이것도 XGBoost 단독 효과라고 부르지 않는다.

## R3 · P1 · 학습창 변경과 고정 라벨 지시가 충돌

- 위치: 수정 전29·38줄. ‘학습11년→5년’이 JM·분류기·평균·공분산 중 무엇을 바꾸는지 불분명했다. JM까지 바꾸면서 원래 JM 라벨을 유지할 수는 없다.
- 근거: [기존 모형](../src/etf_regimes/models.py)과 [후속 모형](../src/etf_regimes/followup_models.py)은 학습창에서 JM·분류기를 적합하고 그 라벨로 평균도 추정한다. 공분산 창도 별도로 달라졌다.
- 반영: 분류기만 줄이는 F01, 공분산만 줄이는 M07, 선택창만 바꾸는 S01, JM/분류기/평균을 함께 바꾸는 P01을 분리했다. P01은 묶음 변경으로 표시한다.

## R4 · P1 · XGB와 월 가중치를 한 요인으로 잘못 묶음

- 위치: 수정 전31–32줄. 기본 대 규제 XGB는 깊이·학습률·L2를 함께 바꾼다. 일별1 대 월별합1은 월 간 상대 비중과 총손실 크기도 함께 바꾼다.
- 근거: [월 가중치 계산](../src/etf_regimes/estimation.py), [분류기 적합](../src/etf_regimes/models.py). 가중치 합은 모델 적합에 그대로 전달되며 규제 계수도 영향을 받는다. 이 의존성을 과소적합의 확정 원인으로 해석해서는 안 된다.
- 반영: F05/F06/F07과 설정 묶음 F08을 구분했다. F03/F04는 총합N과 총합M의 명시적 수식으로 나눴으며, 사전확률 고정 범위를 적었다. I01은 가중치 크기×L2 상호작용이다.

## R5 · P1 · 일요인 진단만으로 알려진 순위 역전을 설명하기 부족

- 위치: 수정 전25·36·40줄. 상호작용 한계는 적었으나 실제 검증할 상호작용을 정하지 않았다.
- 근거: [기존 정책별 결과](followup.md)에서 같은 XGB 예측도 현금 비용 포함·하루 계획과21일 계획 사이에서 두 국면의 성과 순위가 뒤집힌다. 기존24개 연결 실험에는 위험8개·21일의 셀이 없다.
- 반영: 비용 목적 범위8/9개×계획기간1/21일의2×2를 A와 B의 고정 예측에서 완성한다. 실제 비용은 모든 셀에서9개 ETF 다리·5bp로 유지한다. 21일 가정을 원문 오류의 수정으로 부르지 않는다.

## R6 · P1 · 실험 수·지표·다중검정 범위 누락

- 위치: 수정 전27–40·64줄. 어디까지 실행하면 끝인지, 추가 비교에서 어느 구간으로 우위를 판정할지 정해져 있지 않았다.
- 반영: 분류/선택11개+평균/노출/공분산7개+거래/상호작용12개로30개 진단 계정을 닫았다. 기존 세 CER 비교·가족별 max-T 구간은 유지하고 새 진단은 설명용 지표로 제한했다. 평가기간, CER 수식, 비용·샤프·검정력·오류 해석도 명시했다.

## R7 · P2 · 소스 보존과 보고서 변경의 실행 경로 충돌

- 위치: 수정 전45–49줄. 후속 계약은 기존 CLI를 해시로 잠근다. 보고 코드를 변경하면 두 기존 보고서의 소스/README 해시와 봉인도 달라진다.
- 근거: [후속 계약](../configs/followup_contract.json), [기존 검증](../src/etf_regimes/verification.py), [후속 검증](../src/etf_regimes/followup_validation.py). 현재 [보고 코드](../src/etf_regimes/reporting.py)는 후속 파일 존재 여부로 README 생성기를 선택한다.
- 반영: 진단용 별도 진입점·출력 폴더·전체 설정/라벨/튜닝 캐시 키를 요구했다. 보고 변경은 표시 메타데이터와 금융 값 불변 검사 후 재봉인하며 실제 원자료 검증 기록을 새 검증 없이 갱신하지 않는다.

## R8 · P2 · 결과 재사용이 오류 수정을 막을 수 있고 통과 기준도 불명확

- 위치: 수정 전21·64–66줄. 재실행 금지처럼 읽힐 수 있는 문장과 추상적인 독립 검증만 있었다. 원문의 불명확한 부분을 어느 값으로 처리할지도 기록되지 않았다.
- 반영: 검증된 결과만 재사용하고 오류 발견 시 증거·새 계약·영향 범위 재실행을 허용한다. XGB 버전·약세 평균 제한·평활·MinVar 기본 평균 등 미확정 목록을 확장했다. A0 호환성 오차 한계, 세 경계의 자산별 독립 재적합, 미래 교란, 선택 재계산, 전체 수량 재생, 최적성 검사, 복원·공개 CI를 통과 조건으로 적었다.

## 검토 후 상태

- 이번 변경은 두 Markdown 명세 문서에 한정한다. 원자료·기존 계약·금융 코드·성과를 수정하지 않는다.

## 후속 요청 반영 · 원문 실증처럼 성과 개선을 먼저 보여준다

사용자가 ‘논문 실증처럼’이라고 구체화한 뒤 명세를 v3로 보완했다. 기존8개 검토 항목이나 과거 주 설정 기록을 바꾸는 것이 아니라 첫 보고의 산출물과 해석을 구체화한 것이다.

- [원문5절](https://arxiv.org/html/2406.09578v2#S5)은 자산별0/1 성과(표4), 기본 MV·MinVar·EW에 국면 예측을 도입한 전후 성과(표6), 예상수익과 실현수익의 상관(표7)을 제시한다. 작은 고정 CER 효과의 검정력과 이 실증 비교는 다른 질문이다.
- 기존 A51에 자산별 B&H/JM/JM–XGB24개 계정과 기본/국면형 배분 계정이 존재함을 확인했다. 먼저 이 저장 결과로 표4/6 형태의 실증과 NAV·낙폭을 구성한다. D51의30개 새 진단이 먼저 완료되어야만 원문형 성과를 비교할 수 있는 것은 아니다.
- 원문 `Return`과 CAGR, 위험자산/현금 포함 회전율, Calmar 정의를 혼용하지 않도록 적었다. 상관 진단의 수익 구간·현금 기준·집계 방식과 시가 체결의 한계도 명시했다.
- ‘관찰된 개선 방향 유지’와 ‘통계적 우위 확인’을 구분한다. 일부 지표·배분만 개선됐을 때 전체 우위라고 제시하지 않으며, CER 검정력 부족을 이유로 실제 관찰된 성과 차이까지 설명할 수 없다고 말하지 않는다.
- 현재 수정은 명세·검토 기록에 한정된다. 새 표7 상관 진단, 신규 모델, 진단 계정이나 새 원자료 검증을 이미 실행했다고 표시하지 않는다.

## v3 재검수 · v4 반영

이번 검수 대상은 v3의 SHA-256 `8261ff968043a985b6d54f703e88ed0744def0066b3385aa3f9cc0cf77700689`다. 아래 위치는 수정 전 v3 줄 번호이며, 수정 내용은 [현재 명세](redesign-plan.md)에 반영했다. 원문 실증 구성을 추가하면서 생긴 해석·실행상의 빈틈을 검수했다.

### Q1 · P1 · 새 IC를 계약 고정 전에 계산할 수 있는 실행 순서

- 위치: v3의149줄, 7절 마지막 실행 순서. A/B와 IC를 만든 다음 D51 계약을 고정하도록 읽혔다. IC·Calmar·새 구간 통계도 새 금융 지표이므로 정의와 코드의 버전을 먼저 고정해야 한다.
- 수정: 보고 분석 계약과 진단 실행 계약을 분리했다. 원문 준수 감사→보고 코드/정의/입력 고정→원문형 실증 검증→진단 실행 계약/30개 진단 순서로 정했다. 두 계약 모두 이전 결과 열람 사실을 유지한다.

### Q2 · P1 · IC의 예상수익·실현수익·현금일 처리 불명확

- 위치: v3의145–149줄. ‘저장된 예상수익’만으로는 최적화 뒤의0 벡터나 주문 비중을 사용할 수 있었다. 현금 대피일 제외, 하루 날짜 밀림, 목표일 금리의 입력 역류도 막지 못했다.
- 근거: [기존 배분](../src/etf_regimes/study.py)은 강제 현금이면 평균 계산 전에 반환할 수 있고, [후속 배분](../src/etf_regimes/followup_allocation.py)은 별도의 평균/대피 기록을 갖는다. [자료 코드](../src/etf_regimes/data.py)의 지연된 DGS3MO와 실제 BIL 수익도 같은 것이 아니다.
- 수정: p0·상태 평균에서 배분 전 예상수익을 복원하고 현금일도 포함한다. 종가 간 DGS3MO 실현수익과 시가→종가 BIL 초과수익을 각각 식으로 명시했다. 두 모형은 같은 날짜를 쓰며 결측 쌍 삭제를 금지했다. 상수 예측은 상관0 대신 추정 불가 사유를 기록한다.

### Q3 · P1 · 평균 진단의 가중치와 무국면 기준에 신호가 섞일 위험

- 위치: v3의102–110줄. 상태별로 월 가중치를 다시 계산하면 M03의 추정 대상이 달라진다. M06이 A의 약세 제한을 상속하면 ‘무국면’ 예상수익도 XGB 신호에 의존한다.
- 수정: M03 가중치는 전체 가용 이력에서 한 번 계산한 뒤 상태별로 조건화한다. 빈 상태·약세 제한 적용 순서도 명시했다. M06은 강약세 마스크와 제한을 읽지 않으며 JM 신호 교란에도 주문/NAV가 같아야 한다.

### Q4 · P1 · ‘원문과 같은 개선’의 판정이 모호하고 지표 규약이 일부 미확정

- 위치: v3의147·155–156줄. 세 지표와 세 배분 중 어느 조합을 말하는지 구현자가 해석해야 했다. Calmar 식은 표6 수치와 일관되지만 원문의 명시된 산식을 확인한 것은 아니었다.
- 수정: 연 초과수익·샤프·낙폭 차이의 부호와 수치 동일 허용폭을 명시했다. 세 지표·세 배분이 모두 개선될 때의 전체 방향 유지와 일부 개선을 구분한다. 지표 식·실제 종가 노출·회전율 분모·Calmar 적용 규약과 낙폭/변동성0 처리를 기록했다. 이 판정은 관찰된 개선이며 통계적 우위 확정이 아니다.

### Q5 · P2 · 구간별 성과와 대표 그림의 선택 규칙 누락

- 위치: v3의141·151줄. 구간 시작 때 계정을 현금으로 초기화하거나 구간 전 고점을 MDD에 포함하면 다른 전략/통계를 평가하게 된다. 대표 자산도 성과를 본 뒤 고를 수 있었다.
- 수정: 실제 전체 경로의 일별 순수익을 잘라 구간 NAV만1로 재기준화하고 포지션·거래는 초기화하지 않는다. 구간 자체의 고점·관측월수로 통계를 계산한다. 대표 자산은 SPY·IYR·IEF로 고정하고 전체8개도 제공한다.

### Q6 · P2 · 현금 대피와 매매 밴드의 우선순위 누락

- 위치: v3의121줄. 대피 목표와 보유 비중 차이가 작으면 밴드가 강제 현금 신호를 무시할 수 있었다. 상한 위반·정확히2%인 경계의 처리도 정하지 않았다.
- 수정: 강제 현금→신호 상한 위반 해소→밴드 순으로 처리한다. L1 차이가0.02 미만일 때만 보유 수량을 유지하며 경계는 리밸런싱한다. 다음 시가 드리프트를 미리 읽지 않는다. 이는 새 T04의 정의이며 기존 저장 거래 정책을 수정한 것이 아니다.

### Q7 · P2 · 가중치 효과를 L2 하나로 설명할 위험

- 위치: v3의90·125줄. I01은 L2 상호작용만 보는데 가중치 크기는 최소 자식 가중치 같은 다른 절대 문턱에도 작용한다.
- 수정: I01의 설명 범위를 한정했다. 새 적합에는 실제 설정·가중치 합·트리 구조·학습/평가 손실을 기록한다. 기록을 보고 새 하이퍼파라미터 탐색을 자동 추가하지 않는다.

재검수 결과는 문서의 정의·정렬·지표·실행 순서를 보완한 것이다. 실험 수는30개 진단 계정으로 유지하며, 금융 코드·계약·성과나 실제 원자료 검증 기록을 바꾸지 않는다. 구현과 계약 동결이 완료되기 전 새 실증을 실행한 것으로 간주하지 않는다.
